# hPen 기능 개선 점검

작성일: 2026-10-30. Windows 11 안정성을 최우선으로 한 재제작 기능 제안.
기존 hpen-deprecated 구현과 앞선 조사 보고서를 기준으로 했다. 실행 검증 전 정적 점검이며, 제안은 구현 완료 기능을 뜻하지 않는다.

## 판단

새 도형을 늘리는 것보다 입력·모드 전환, 필기 보존, 수정, 캡처 후 활용 흐름을 개선하는 효과가 크다. 첫 버전은 정지 화면 필기를 중심으로 만들고 라이브 오버레이·영상 녹화 등은 후순위로 둔다.

## 1. 첫 버전에서 우선 개선

| 항목 | 기존 근거 또는 불편 | 제안 동작 | 완료 기준 |
|---|---|---|---|
| 도구 선택 | ShapeFactory에 pressedKey를 전달하는 키 기반 선택 | 기존 키 조작을 선택적으로 유지하고 클릭하면 유지되는 도구 버튼 제공 | 키를 계속 누르지 않아도 마우스만으로 모든 기본 도구 사용 |
| 현재 상태 표시 | 모드·색·두께를 기억해야 하는 부담 | 작은 도구 모음에 도구·색·두께·정지 화면 상태 표시 | 현재 입력 결과를 그리기 전에 예측 가능 |
| 텍스트 편집 | 자체 한글 조합과 수동 Backspace 처리 | OS IME, 커서 이동·범위 선택·붙여넣기·기존 텍스트 재편집 | 한글 조합 중 도형 단축키가 실행되지 않음 |
| 빠져나오기 | Esc가 텍스트 확정·선택 해제·필기 종료를 모드별로 수행, 기본 모드 종료 시 clear | 조합 취소/도구 작업 취소 → 선택 해제 → 화면 닫기를 명확히 정의하고 화면 내용 보존 | Esc 반복 후 원래 앱으로 복귀, 필기 재열기 가능 |
| 실수 복구 | 단일 C로 전체 지우기, 이미지 복사 중심 이력 | 전체 지우기·이동·삭제·스타일 변경 모두 undo, 다시 그리면 redo 정리 | 지우기 직후 Ctrl+Z로 정확히 복원 |
| 단축키 | Alt+숫자 고정 등록, 숫자패드 슬롯 | 사용자 변경·등록 실패 표시·기능별 해제·트레이 대체 실행 | 충돌해도 앱의 모든 기본 기능 실행 가능 |
| 화면 선택 | 현재 커서 모니터 중심 | 현재 모니터 기본값, 명시적 모니터 선택과 직전 선택 기억 | 배율이 다른 모니터에서도 캡처와 필기 위치 일치 |
| 저장 피드백 | 저장/클립보드 실패를 콘솔에 출력하는 경로 | 성공 표시, 실패 이유와 재시도, 실패 시 원본 유지 | 저장 실패나 대화상자 취소로 필기 소실 없음 |

Esc의 최종 세부 동작은 실제 강의 사용으로 조정할 수 있다. 확인 대화상자를 매번 띄우는 대신 자동 보존과 복구 가능한 동작을 우선한다.

## 2. 기존 캡처의 구체적 수정 후보

기존 `ScreenData.getWidth()/getHeight()`는 커서 좌표에서 시작 좌표를 빼고, `CaptureFrame.saveScreen()`은 너비·높이가 0 이하이면 중단한다. 따라서 왼쪽 또는 위쪽으로 역방향 드래그한 영역이 저장되지 않을 수 있다. 이 경로는 코드상 확인되며 실제 UI 재현은 아직 하지 않았다.

또한 테두리 두께만큼 저장 영역을 줄이고 있다. 선택한 영역과 결과 이미지의 크기가 달라질 수 있어, 새 구현에서는 장식 테두리를 결과에서 분리해야 한다.

제안:

- 네 방향 드래그 모두 동일하게 처리하고 0 크기 선택은 다시 선택할 수 있게 한다.
- 선택 중 가로×세로 픽셀 크기와 확대 미리보기 표시.
- 선택 후 핸들로 크기·위치를 조절하고 Enter 또는 버튼으로 확정.
- 빠른 캡처 사용자는 드래그 후 즉시 복사하는 모드도 선택 가능.
- 복사·저장·필기 열기를 후속 동작으로 제공하고 기본값 기억.
- 클립보드 복사와 파일 저장을 함께 수행할 수 있게 한다.
- 최근 캡처 영역 반복 사용, 전체 모니터 캡처를 제공한다.
- 창 단위 캡처는 후속 단계로 검증한다.

## 3. 필기 수정 기능

기존 선택·이동 경로는 존재하므로 전부 없는 기능으로 취급하지 않는다. 재제작에서는 다음 편집을 일관된 객체 단위 동작으로 완성하는 것이 목표다.

- 클릭/영역으로 선택, 복수 선택, 이동, 크기 변경, 복제, 삭제.
- 선택한 도형의 색·선 두께·투명도 변경.
- 객체 지우개: 잘못 그린 화살표 하나만 삭제. 부분 획 지우기는 나중에 추가.
- 형광펜: 선이 겹쳐도 과도하게 진해지지 않도록 합성 방식 검증.
- Shift로 원·정사각형·수평/수직선 제약. 텍스트 편집과 모드 충돌 방지.
- 텍스트 더블클릭 재편집, 글자 크기 변경, 배경/테두리 선택.
- 화면 맞춤/100% 보기, 확대 중 이동. 저장 시 화면 확대율과 무관한 원래 해상도 유지.

## 4. 필기 보존과 강의 흐름

### 필기와 원래 화면 사이 이동

필기 잠시 숨김 → 원래 앱 조작 → 필기 복귀를 제공한다. 정지 배경을 유지하는 동작과 새 화면으로 배경을 갱신하는 동작은 분리한다. 배경 갱신 시 기존 표시가 새 내용과 어긋날 수 있으므로 기본값은 새 페이지 생성이다.

### 메모리 슬롯을 페이지 목록으로 확장

10개 숫자패드 슬롯의 빠른 접근은 유지하되 썸네일·제목·버튼으로도 선택하도록 한다. 슬롯 덮어쓰기 전 복구 경로를 제공한다. 화이트보드도 여러 페이지로 넘기고 복제할 수 있게 한다.

### 이미지와 편집 가능한 프로젝트 분리

PNG는 공유용, 별도 프로젝트 파일은 배경과 도형·텍스트·페이지를 보존하는 용도로 둔다. 이전 이미지를 다시 열어 이어 그리기와, 도형을 계속 편집하는 프로젝트 열기를 구분한다. 자동 복구는 명시적 저장과 별도로 제공하고 보관 기간·삭제·끄기를 지원한다. 캡처에 민감한 화면이 포함될 수 있으므로 자동 보관 사실을 사용자에게 보여준다.

### 발표 보조

커서 강조·클릭 표시·시간이 지나면 사라지는 레이저 포인터를 후보로 둔다. 첫 단계에서는 필기 창 내부에 한정해 입력 충돌 범위를 늘리지 않는다. 강의용 밝은/어두운 배경과 최근 색·두께 프리셋도 유용하다.

## 5. 확대 기능 정리

사용자 관점에서 다음 동작을 구분한다.

1. 정지 화면 확대: 캡처한 화면을 확대하면서 필기. 첫 구현 대상.
2. 라이브 확대창: 움직이는 화면의 커서 주변을 확대. 확대 위치 고정/커서 추적 선택.
3. OS 전체 화면 돋보기: 시스템 확대 기능과 통합. 별도 검증 대상.

공통적으로 현재 배율 표시, 기본 배율 복귀, 확대창 위치 고정, 화면 가장자리 처리, Esc 복귀가 필요하다. 라이브 확대는 자기 창이 반복해서 잡히는 현상과 원래 앱 클릭 가능 여부를 검증한다. 세 기능을 같은 방식으로 동작한다고 안내하지 않는다.

## 6. 권장 구현 묶음

### 첫 안정 버전

트레이·변경 가능한 단축키, 모니터 캡처, 정지 화면 필기·화이트보드, 기본 도형·자유곡선·표준 한글 텍스트, 도구 모음, undo/redo, 복사·PNG 저장, 필기 잠시 숨김/복귀. Windows 11 반복 사용·IME·듀얼 모니터 검증을 완료 조건으로 둔다.

### 두 번째 버전

선택·수정·지우개·형광펜, 페이지/슬롯 썸네일, 프로젝트 저장·자동 복구, 최근 영역 재캡처, 정지 화면 확대. 첫 버전에서도 실수로 닫은 내용의 세션 내 보존은 제공한다.

### 이후 검증

라이브 줌, 창 캡처, 펜 압력·손바닥 오입력 방지, 다른 앱 위 라이브 필기, 타 OS 확장. 라이브 오버레이는 포커스·클릭 통과·입력 전환 복잡도가 커서 별도 단계로 둔다.

OCR, 영상 녹화, 클라우드 동기화, 협업은 현재 핵심 목적에 비해 범위가 크므로 보류한다.

## 7. 대표 사용 시나리오로 확인할 것

- 강의 화면을 열고 단축키로 진입해 화살표·한글 설명을 쓰고 복사한 뒤 원래 앱으로 복귀한다.
- 한글 조합 중 Q/C/Esc/Backspace/붙여넣기를 사용해도 도형 선택·전체 지우기가 잘못 실행되지 않는다.
- 전체 지우기·도형 이동·텍스트 수정 후 undo/redo 결과가 정확하다.
- 캡처를 네 방향으로 선택하고 같은 픽셀 크기의 결과를 얻는다.
- 저장 취소·클립보드 오류·예기치 않은 닫힘 뒤 내용을 복구한다.
- 숫자패드 없는 노트북과 배율이 다른 듀얼 모니터에서 마우스만으로도 기본 기능을 사용한다.
- 필기/원래 앱 전환을 반복해도 키가 눌린 상태로 남거나 다른 앱 입력이 막히지 않는다.
